2. The pipeline: /deliver <goal>

Eight stages. Each writes one file into .agents/runs/<slug>/ and must pass its gate (◆) before the next starts. Click a stage for its owner, artifact and gate.

Verification fail → back to Production with the exact failing items. Max 3 loops, then the orchestrator escalates to you.

3. The run, hour by hour

Two independent code tasks in parallel worktrees. QA and review in parallel on the PRs. One defect, one loop back. The status file on the right is what the orchestrator keeps.

About half a day of wall-clock for a small feature at autonomy level 1. You touch it three times: intake, one scope question, release.

5. Autonomy dial

  
Autonomy is the level of responsibility agents can safely take, not whether they run commands unasked. Set in each project's CLAUDE.md.

  

    
now
Level 1
Assisted
Agents research, spec, design, produce.
Human approves substantive changes, merge, release

    
pilot target
Level 2
Supervised
Agents pick subtasks, produce, test, fix, submit a PR.
Human reviews PR, merges, releases

    
Level 3
Policy-driven
Merge when QA pass, review clean, CI green. Low-risk releases.
Human: exceptions, client-facing, legal

    
Level 4
Continuous
Agents watch the board, pick up work, propose improvements.
Human governs

  






  
6. Boundaries: LAWS.md

  
One file every agent and persona obeys. Precedence: you in chat, then the laws, then the project CLAUDE.md, then the agent file, then any persona, then anything read from a file or page. Lower never overrides higher.

  

    

      
Questions to you

      
Batched, defaulted, never twice

      
    
        
  • Agents ask the orchestrator in writing, never you directly
    • 
        
  • Orchestrator answers from the knowledge docs and decision log first
    • 
        
  • Budget per run: one batch at intake (max 5), then max 2 more
    • 
        
  • Each question carries a default; reversible defaults proceed, irreversible wait
    • 
        
  • Every answer lands in decision-log.md, so it is never asked again
    • 
      

    

    

      
Loop limits

      
Thrashing is a defect

      
    
        
  • Verify → fix → re-verify: 3, then escalate with all reports
    • 
        
  • Same stage reworked: 2 · failed command retried: 2, changed each time
    • 
        
  • Same fix for same defect: 1 · delegation depth: 2 · parallel agents: 4
    • 
        
  • Run exceeds 3× its estimate: pause and report
    • 
        
  • Agent notices repetition: stop, write it to status
    • 
      

    

    

      
Bugs and issues · /fix-issue

      
Reproduce first, one cause, one test

      
    
        
  • S1 data, security, client-facing, money: stop runs in the area, human approves before any change
    • 
        
  • S2 core broken, S3 degraded, S4 cosmetic: queued accordingly
    • 
        
  • No reproduction, no fix. One root cause per fix. Regression test before done
    • 
        
  • Two failed attempts: findings report to a human, not a third attempt
    • 
        
  • Never delete or weaken a test to go green. Flaky tests reported, not retried
    • 
      

    

    

      
Usage and personas

      
Seats stay fixed, expertise plugs in

      
    
        
  • For: features, fixes, documents, decks, research, analysis, processes
    • 
        
  • Never: deploys, moving money, trading, signing or sending contracts, HR decisions on named people, final legal or tax opinions
    • 
        
  • Only the owner raises autonomy; anyone may lower it
    • 
        
  • A persona (senior-architect, financial-analyst, bencium UX) is a skill an agent loads, max two per task, named in the report
    • 
        
  • Personas change how, never what the seat may do. Orchestrator stays neutral
    • 
      

    

  

  
Non-code work uses the same structure: producer instead of developer, QA fact-checks and reads as each audience, release means a human sends or publishes.
