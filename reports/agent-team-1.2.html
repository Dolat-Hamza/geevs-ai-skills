Bottom line. Your main session runs the process, three agents do isolated work, and anything that must hold is enforced by scripts, permission rules and hooks. Since 1.2.0, a run can only be released with proof. For code, its new tests fail on the old code and pass on the new. For documents, every claim, quote and figure traces to a source line. Live testing found 14 defects across 1.0.0, 1.1.1 and 1.2.0, all fixed. The 1.2.1 fixes are proven by unit tests and by replaying real data from the live run. A full live run on 1.2.1 hasn't happened yet.

How it works

/geevs-agent-team:deliver <goal> interview ─▶ research (0–3 researchers, Haiku) ─▶ spec ─▶ [you approve] ─▶ builder (Sonnet, own worktree) ─▶ reviewer (Sonnet, cannot edit, records evidence) ─▶ proofs: code = tests fail before, pass after · documents = every figure traced to a source line ▲───────── failed criteria or proofs, at most 3 reviews ─────────┘ ─▶ release summary ─▶ [you push / merge: the permission rules ask first]

Limits and open items

Known limits

  • Permission rules match command prefixes, so they don't stop bash -c or scripts. Use Claude Code sandboxing for a hard boundary.
  • Rules and hooks apply only in clones that ran setup, with Claude Code opened in that folder.
  • The document proof checks that each figure is quoted, declared or correctly calculated. It doesn't check that the reasoning between figures is right.
  • Test files are recognised by path (tests/, test_*, *.test.*, *_test.*).
